# drahtseilakt-toolbox

[English](README.md) · **Русский** · [Deutsch](README.de.md) · [简体中文](README.zh.md)

Готовит уровни для [Drahtseilakt](https://github.com/eugene-vereshchagin/drahtseilakt), нового движка Ballance, на
машине игрока и из его собственной копии игры. Игра только играет то, что лежит в её папках уровней; всё тяжёлое,
что делает уровни современными, живёт здесь, и игре ничего из этого не нужно.

```
drahtseilakt-toolbox                     (окно)
drahtseilakt-toolbox remaster [--levels LIST] [--scale N] [--model NAME] [--relief S] [--data DIR]
drahtseilakt-toolbox sounds [--data DIR]
drahtseilakt-toolbox remaster-open DIR [--scale N] [--model NAME] [--relief S]
drahtseilakt-toolbox remaster-nmo FILE.nmo [--scale N] [--model NAME] [--relief S]
drahtseilakt-toolbox relief DIR [--scale N] [--relief S]
drahtseilakt-toolbox import-maps DIR [--to DIR] [--catalogue FILE] [--unsorted DIR]
drahtseilakt-toolbox import-maps --refresh DIR --catalogue FILE [--source DIR] [--unsorted DIR]
```

**Папки (2026-11-12).** В `levels/` игры лежат `ballance-original/` (ваша копия), `ballance-remaster/` (сюда пишет `remaster`) и `user-levels/` (сюда по умолчанию пишет `import-maps`; прежние имена `original/`, `remastered/` и `downloaded/` игра переименовывает при первом запуске). Уровень считается уровнем, только если он лежит в собственной именованной папке, где есть либо один файл `.nmo`, либо уровень в открытом формате, и файл описания `level.txt`: именно так раскладывает `import-maps`.

`remaster-open` переделывает папку одного уровня в открытом формате на месте (скруглённые формы, крупные текстуры, рельеф кладки; простые оригиналы остаются в `textures.original/`, повторный запуск ничего не увеличивает дважды). `remaster-nmo` делает рядом с картой сообщества папку `FILE.remaster/`: её вид и картинки, которые игра накладывает на сетки карты. Мод «Назад в 2004» показывает оба набора простыми.

Запущенный без команды, toolbox открывает окно (Linux X11 или Wayland, Windows, macOS; последние выбранные модель и
увеличение оно помнит в `toolbox.txt` в папке данных игры): ваша копия игры, во сколько
раз увеличивать, модель Real-ESRGAN, рельеф, кнопка «Сделать», прогресс по уровням и частям с отменой, результат и
текстура до и после. Тексты на английском, русском, немецком, упрощённом китайском, французском, испанском и итальянском — по языку системы или на выбор
в окне. Окно выглядит как собственное меню игры (закатное небо, тёмные панели в рамке, кнопки-капсулы с шариком,
надписи шрифтом Tektur, как в игре) и рисуется самим toolbox: копия игры для этого не нужна, картинок он не несёт.
В окне два раздела — «Ремастер оригинальных уровней» и «Импорт любительских карт», в каждом одна главная кнопка;
модель Real-ESRGAN и рельеф свёрнуты в «Дополнительно». Шрифты в программу не встроены: окно
при запуске читает файлы шрифтов самой игры (Tektur, Noto Sans и для китайского Noto Sans SC; SIL OFL, лежат в
`assets/fonts/` игры вместе с лицензиями) там же, где игра ищет свои ресурсы (рядом с программой, в портативной папке,
в дереве игры при сборке из исходников), иначе в папке `fonts/` рядом с toolbox. Без Noto Sans SC китайский берёт
шрифт из системы (Noto CJK, Microsoft YaHei, PingFang...); без Tektur или Noto Sans toolbox пишет, какого файла нет
и где он искал, и окно не открывает.

`remaster` переводит оригинальные уровни из копии в `levels/ballance-remaster/` игры (открытый формат), даёт каждому
уровню более круглые формы (записываются в уровень рядом с исходными мешами, физика по-прежнему берёт исходные, так
что прохождения те же) и увеличивает текстуры в N раз (по умолчанию 4; 1 — не трогать). С Real-ESRGAN текстуры
получают детали, без него увеличиваются фильтром Lanczos (как и текстуры меньше 64 пикселей: на них он выдумывает
детали). Real-ESRGAN ищется в `realesrgan/` рядом с программой
toolbox, затем в PATH; используемая версия закреплена в [third-party.txt](third-party.txt). Оригиналы сохраняются
в `textures.original/`. Части каждого уровня (шары, модули, трансформер) переделываются так же в его собственную
папку `game/` вместе с небом, частицами, тенью и звуками, и уровень играет без файлов уровней копии (open-format.md
игры). Оригинальные уровни при каждом запуске
строятся заново из копии. Повторяющаяся плиткой текстура увеличивается вместе с полосой своего противоположного края, поэтому на стыках плиток
нет швов. С `--relief S` каждая освещаемая текстура получает ещё и карту
нормалей силы S, сделанную из её собственной картинки; игра использует её в ремастер-уровнях. По умолчанию выключено:
рельеф угадывается по картинке и углубляет каждую трещину и щель (при 8 мир выглядел выеденным кислотой); держите его
низким, 1–3. Кладка делается всегда: где текстура показывает кирпич в бетоне (кирпичные пояса полов), кирпичи
узнаются по цвету (терракота среди бежевого или серого), поднимаются, швы между ними утапливаются, и игра рисует это с
параллаксом, так что кирпичи выступают и при взгляде вскользь; дерево, камень и металл не трогаются. `relief DIR`
заново делает рельеф одной папки уровня в открытом формате, не ремастеря её. `--model` выбирает другую модель Real-ESRGAN, положенную в его папку `models/` (по умолчанию —
realesrgan-x4plus, она идёт в комплекте). `remaster` (или одна команда `sounds`) делает ещё и звуковую тему «оригинальная» в папке данных игры из звуков и
музыки копии; это оригинал, поэтому она остаётся на машине игрока. После обновления toolbox запустите снова — уровни обновятся.

Рядом с каждой большой картинкой (от 512 x 512) `remaster` пишет её и в готовом для видеокарты виде (`name.dtx`:
BC1 для непрозрачной цветной картинки, BC7 для картинки с альфой и для карты нормалей, со всеми мипами; кодировщик
свой). Игра загружает их вместо PNG: уровень в 4K грузится за пару секунд и занимает около пятой части видеопамяти.
PNG остаются (для следующего запуска, и игра возвращается к ним при надобности); картинка, увеличенная один раз за
запуск, копируется во все части с такой же, так что запуск короче, а игра загружает её один раз. У уровней, сделанных
старым тулбоксом, таких файлов нет: запустите `remaster` ещё раз.

`import-maps DIR` раскладывает скачанную коллекцию любительских карт (распакованный архив: папки любой глубины,
картинки, документы) в `levels/user-levels/` игры (или `--to DIR`) так, как их показывает игра (levels.md игры,
«Уровень — это папка»): папка на карту с её `.nmo`, картинкой рядом как `preview.jpg`/`.png` и `level.txt`, где
сказано, откуда она (и полное название, если имени папки пришлось потерять символы). Безликое имя файла
(`Level_07.NMO` в «45-Degree Rotated Maps») называется по коллекции («45-Degree Rotated - Level 07»); один и тот же
файл, найденный дважды, — один уровень; упакованные архивы (`.tar.gz`, `.zip`...) не открываются, а откладываются (ниже);
имена годятся для Linux, Windows и macOS (без зарезервированных имён, без точек и пробелов в конце, не длиннее 40
знаков, обрезаются по слову с «…», второй «Hello Mars» становится «Hello Mars (2)»). По ссылкам не ходит, глубина и
количество ограничены, источник только читается, каждый уровень пишется в скрытую папку и переименовывается на
место. Повторный запуск добавляет только новое. В окне то же самое: поле и кнопка Import.
У каждого поля пути в окне есть кнопка «Обзор…» (у копии игры ещё «Образ…» для образа диска: .cue, .bin, .iso), она открывает системный выбор; путь проверяется как введённый, папка запоминается. В Linux нужен xdg-desktop-portal с бэкендом (-gtk, -kde, -gnome); без него поле остаётся для ручного ввода.
Распаковывайте скачанное вне `levels/user-levels/` (например, в Загрузки): источник внутри папки, в которую идёт
импорт, не принимается. Нечитаемая папка скачанного пропускается и называется; в печатаемых именах управляющие
символы экранируются.

Когда карты созданы, программа просит игру (`drahtseilakt` рядом или в PATH) проверить каждую: в результате у каждой карты вердикт (идёт полностью, идёт с отличиями, может не проходиться, не загружается) и что игра в ней пока не поддерживает: неизвестные блоки скриптов, стоящие на месте части под управлением скриптов, текстуры, которые автор не приложил, звуки скриптов. Проверка хранится рядом с картой как `report.txt` и видна в списке скачанных карт в игре. Без игры под рукой карты всё равно импортируются; позже запустите `drahtseilakt --audit-report DIR`.

С `--catalogue FILE` (каталог сообщества, `CustomMapList.md` из
[BallanceCustomMaps](https://github.com/pseudoacetyl/BallanceCustomMaps)) каждая карта ищется по имени файла и имени
её папки (регистр, знаки препинания, пробелы, полноширинные символы и «v1.0»/«V1.0»/«1.0» не важны; номер версии,
которого нет в каталоге, пробуется отброшенным, но никогда не как другая версия; имя, общее у двух карт, или короче
трёх знаков не находит ничего; имя папки считается только для единственной карты в ней). Найденная карта получает в
`level.txt` `title =` (английское название), `title.zh =` (оригинальное, если оно другое и китайское), `author =` и
`difficulty =`: шкала игры 1–10, поэтому **шкала каталога 1–5 (с половинками) удваивается** (3.5 становится 7;
диапазон вроде 2.5–3 берёт середину с округлением вверх: 6); если сложности в каталоге нет, она не пишется. С
каталогом карта, которой нет ни в нём, ни readme рядом (`.txt`, `.md` или `.nfo`, или документ, названный как readme
или как карта), не импортируется: как и упакованные архивы, она копируется в **папку неразобранного** (`--unsorted
DIR`, по умолчанию `community-unsorted` рядом с папкой уровней) под своим путём в скачанном, а `README.txt` там
перечисляет каждый предмет и почему он отложен, — чтобы разобрать руками. Карта с readme, но не из каталога,
импортируется с названием по имени и без сложности. Каталог читается как чужой файл: не больше 4 МиБ, 20 000 строк и
1024 знаков в ячейке, испорченные строки пропускаются, значения очищаются.

`import-maps --refresh DIR --catalogue FILE --source DIR` приводит уже импортированную папку уровней
(`levels/user-levels`) к каталогу на месте: `level.txt` каждого уровня пишется из каталога (поиск по строке `source =` и
имени папки; комментарий, строка `source =` и прочие строки сохраняются), а папка, которая не один уровень (нет карты
или их несколько), или чьей карты нет ни в каталоге, ни readme (в её папке или рядом с источником в коллекции
`--source DIR`, относительно которой записаны пути `source =`), переносится в папку неразобранного (переименованием на
том же диске; ничего не удаляется). Переносятся только папки, сделанные import-maps (`level.txt` со строкой
`source =`); уровень, чей источник нельзя посмотреть, остаётся. Строки, для которых в каталоге нет значения (свой
`author =`), сохраняются.

Правила: toolbox работает только с данными самого игрока; он не поставляет данные игры (звуковые темы и переделанные уровни остаются на машине игрока), никогда не выходит в сеть, не трогает оригинальную копию игрока и не меняет физику игры (то, что он добавляет в уровень, только рисуется).

## Загрузки и сборка релизов

У toolbox свои релизы: [github.com/eugene-vereshchagin/drahtseilakt-toolbox/releases](https://github.com/eugene-vereshchagin/drahtseilakt-toolbox/releases) (версия 0.1.0; первый релиз ещё не опубликован). Он также входит в портативные архивы игры и в её установщик для Windows (ярлык в меню «Пуск»); общая картина того, что где поставляется, описана в [docs/drahtseilakt/distribution.md](https://github.com/eugene-vereshchagin/drahtseilakt/blob/main/docs/drahtseilakt/distribution.md) репозитория игры.

Релизы собирает GitHub Actions (`.github/workflows/toolbox-release.yml`, запуск вручную или тегом `X.Y.Z`; тег
создаёт черновик релиза со всеми пакетами и `SHA256SUMS`, который публикует владелец). В именах файлов остаётся версия (ниже `<version>`), чтобы её было видно. Самый свежий релиз: `https://github.com/eugene-vereshchagin/drahtseilakt-toolbox/releases/latest`; скрипт или сайт берёт его из API (`GET https://api.github.com/repos/eugene-vereshchagin/drahtseilakt-toolbox/releases/latest`), выбирает в `assets[]` файл, чьё `name` подходит, например, под `drahtseilakt-toolbox-*-windows-x86_64-setup.exe`, и использует его `browser_download_url`:

| Система | Файлы |
|---|---|
| Windows x86_64, arm64 | `drahtseilakt-toolbox-<version>-windows-<arch>-setup.exe` (установщик), `drahtseilakt-toolbox-<version>-windows-<arch>.zip` (портативный) |
| Linux x86_64, aarch64 | `drahtseilakt-toolbox-<version>-linux-<arch>.tar.gz` (портативный), `drahtseilakt-toolbox_<version>-1_<amd64\|arm64>.deb`, `drahtseilakt-toolbox-<version>-1.<x86_64\|aarch64>.rpm` |
| macOS arm64, x86_64 | `drahtseilakt-toolbox-<version>-macos-<arch>.tar.gz` (портативный; без подписи: см. `README.txt` внутри) |
| FreeBSD x86_64 | `drahtseilakt-toolbox-<version>-freebsd-x86_64.tar.gz` (экспериментально) |

В каждый пакет входят OFL-шрифты игры в `fonts/` рядом с программой (окно читает их оттуда), поэтому ни один пакет не
зависит от пакета игры. Real-ESRGAN (версия закреплена, SHA-256 проверяется, `third-party.txt`) включён для Linux
x86_64, Windows x86_64 и macOS; в остальных пакетах `README.txt` сообщает, что его нет, и инструмент увеличивает
текстуры методом Ланцоша. `.deb` и `.rpm` кладут программу, шрифты и Real-ESRGAN в `/usr/lib/drahtseilakt-toolbox/`
со ссылкой в `/usr/bin`. `scripts/ci-package.sh OS ARCH BINARY VERSION` делает пакеты из готового бинарника.

## Сборка

Чтение уровней у toolbox общее с крейтами игры, подключёнными по пути: нужен клон репозитория игры рядом, в `../drahtseilakt`. Затем
`cargo build --release --offline` (сеть не нужна; зависимости закреплены в `Cargo.lock`). Для Real-ESRGAN распакуйте закреплённый архив в `third_party/realesrgan/` и
сделайте ссылку `target/release/realesrgan` на эту папку. Репозиторий игры закрытый: CI забирает его с секретом
`GAME_DEPLOY_KEY` (SSH-ключ развёртывания только для чтения).
